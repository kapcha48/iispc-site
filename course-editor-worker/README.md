# IISPC — подключение визуального редактора курса

Пилот виден только на странице `/preview/archive/course-14937/`. Без серверного адреса это демо: можно посмотреть результат, но нельзя записать его в GitHub. Рабочая форма Pages CMS остаётся доступной. Домен и хостинг сайта не меняются.

## Однократная настройка владельцем

1. В аккаунте Cloudflare на плане Workers Free создайте поддомен `workers.dev`, если он ещё не настроен. Сервис называется `iispc-course-editor`; адрес будет `https://iispc-course-editor.<поддомен>.workers.dev`. Не подключайте к нему домен `iispc.org`.
2. В аккаунте GitHub владельца создайте закрытый GitHub App. Homepage URL — `https://kapcha48.github.io/iispc-site/preview/archive/course-14937/`, Callback URL — адрес сервиса с окончанием `/auth/callback`. Отключите Webhook. Права репозитория: `Contents: Read and write` и обязательное `Metadata: Read-only`. Права `Actions`, доступ к остальным репозиториям, членам организации и личным данным не требуются. Установите приложение только для `kapcha48/iispc-site`.
3. Запустите `pnpm exec wrangler deploy --config course-editor-worker/wrangler.toml --var WORKER_ORIGIN:<адрес-сервиса>`. Добавьте через настройки **этого Worker** зашифрованные секреты `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `SESSION_KEY`. Последний — случайные 32 байта в base64url. Секреты не добавляйте в GitHub Pages, файлы проекта, сообщения или клиентский код.
4. В настройках репозитория GitHub создайте обычную переменную Actions `IISPC_COURSE_EDITOR_URL` с адресом Worker без завершающего `/`. Пересоберите сайт существующим workflow публикации, не передавая `payload`. Проверьте отказ для другого GitHub-аккаунта и успешный вход владельца перед использованием редактора.

Сохранение проверяет идентификатор владельца, версию файла и допустимые поля. Приложение GitHub имеет право записи в выбранный репозиторий, но сервер всегда пишет только в `content/programs/course-14937.md` на ветке `preview`. На первом этапе вместо загрузки новых файлов доступны несколько существующих обложек. Записи ветки `preview` открыты, так что здесь не следует хранить приватные данные. Чтобы подтвердить публикацию **всех** просмотренных изменений на основном сайте, используйте существующее действие Pages CMS.

Одноразовая проверка пакета без публикации: `pnpm exec wrangler deploy --dry-run --config course-editor-worker/wrangler.toml`. Локальные тесты используют имитацию GitHub API и ничего не отправляют во внешний репозиторий. Чтобы отключить пилотное сохранение, уберите переменную Actions, пересоберите сайт и отзовите установку GitHub App.
